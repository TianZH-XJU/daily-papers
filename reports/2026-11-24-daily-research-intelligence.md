## 二、执行摘要：今天的研究信号

今天的论文并不是简单地在某个模型结构上“再加一层”。更明显的变化，是研究者开始把过去常被当作外围工程的因素——机器人动作接口、执行反馈、记忆组织、数据标签质量、推理调度与结果验证——提升为方法本身的一部分。

最突出的主线是 **具身智能从动作生成走向可验证的物理目标完成**。Motion Mamba 2.0 解决长时间动作流中的历史状态与推理延迟；Embo-Harness、RUIBench 和 WeaveVLA 说明同一个基础模型，换一套动作接口、观测组织或空间关系表示，表现可能发生大幅变化；WorldLeague 则把“答对问题”与“真正完成物理目标”拆开评分。DexDuet、MomentMem、HIVE-Bench、SWEEP-Bench进一步把接触、关键视觉时刻、patch 级表征和运动速度纳入评价。

另一条主线是 **世界模型开始承担可执行预测，而不只是生成逼真的未来画面**。Native LAM 从视频世界模型中蒸馏潜在动作，Plan4D 将 RGB 未来与 4D 几何对齐，PersistWorld 维护可随时间演化的场景状态，Fast-JEPA 则减少规划阶段的递归 rollout。它们共同指向一个产业问题：模型预测的未来是否足以支持下一步决策，而不只是看起来合理？

Agent 研究也出现了更务实的转向。ReWeave、Embodied-Harness、MMMem、MomentMem、MORSE 和 ToolSmith 不再只讨论“更强的推理模型”，而是让系统从执行记录中提取经验、整理证据、生成工具或重构工作流。软件工程 Agent 领域的 SWE-Gym-Verified 则提醒行业：如果隐藏测试给错奖励，再强的强化学习也可能把错误行为训练得更牢。

**今天最值得产业团队认真跟踪的，不是单一榜单第一名，而是三种可迁移的工程原则：**

1. 把动作、工具和环境接口设计成可控、可组合、可验证的协议；
2. 把历史经验保存为带来源、可更新、可追溯的状态，而不是无限堆叠上下文；
3. 把评测从最终回答扩展到真实结果、过程证据、资源成本和失败恢复。

## 三、研究热点与趋势

### 3.1 具身智能：从“能动”到“做成”

Motion Mamba 2.0、Embo-Harness、RUIBench、WeaveVLA、DexDuet、MomentMem、HIVE-Bench 和 SWEEP-Bench 分别从时序记忆、执行 harness、动作接口、三维关系、接触保持、视觉记忆、patch 表征和速度感知切入。它们共同说明，机器人能力并不只由 VLA 主干网络决定。观测从哪里来、动作以什么粒度表达、何时反馈、失败如何归因，都会改变最终成功率。

### 3.2 世界模型：从生成视频到提供可用状态

Plan4D、Native LAM、PersistWorld、Fast-JEPA 和 ViDecide 都在压缩“预测—规划—执行”之间的距离。值得注意的是，几篇论文不再把生成质量作为唯一目标，而是引入几何一致性、潜在动作、持久世界状态、终点预测和显式停止决策。接下来真正的分水岭，可能是模型能否在动态、分布外和有时限的环境里持续给出可靠状态。

### 3.3 Agent 工程：记忆、工具与自我改进进入系统层

ReWeave、Embodied-Harness、MMMem、MORSE、ToolSmith、Wactorz 和 GameAnything 体现出一种系统化倾向：Agent 的“经验”需要被结构化，工具需要可扩展，运行时需要容错，长期执行需要监督和迁移。此类方法的价值在于可以不更新底层模型参数就改进系统，但也会把风险转移到记忆污染、工具权限、代码生成和回归测试上。

### 3.4 评测与数据质量：从分数转向证据

WorldLeague 把物理进展与任务成功拆开；RUIBench 发现 Agent 会在可见失败后仍宣称成功；SWE-Gym-Verified 审计强化学习奖励标签；GameDojo 和 SWEEP-Bench 引入实时交互和速度维度；GUI 环境完整性研究显示训练环境的裁剪方式会改变泛化表现。评测正在从“有没有分数”转向“分数是否对应正确能力”。

### 3.5 推理效率：算法、架构与系统协同

Motion Mamba 2.0 的状态提交和 CUDA Graph 优化、NoHairCache 的 KV 淘汰、Feedback Shortcut 的 speculative decoding、Loop-PP 的循环流水并行、UNIFIED 的单 Transformer 潜扩散，都说明效率优化已不局限于减少参数量。工程上应同时观察吞吐、端到端延迟、显存、输出一致性和任务质量，不能用单一速度数字代替部署评估。

### 3.6 多模态垂直应用：小模型与结构化输出仍有空间

WeMM-Ecom、Typhoon OCR 2、SAVIOR、VIVID、Prism、ViDiHand2 和 ApexID 展示了面向电商、财务文档、医疗影像、文本版面、手部几何与动物身份识别的任务化路线。其共同特征是把通用表征与领域结构约束结合，而不是一味扩大模型规模。

# A. 具身智能、机器人控制与物理世界模型

### 1. [Motion Mamba 2.0: Autoregressive Diffusion Mamba for Long-Horizon Humanoid Control](https://arxiv.org/abs/2611.29897) · [GitHub](https://github.com/AIGeeksGroup/MotionMamba2.0)

1. **针对什么问题：** 人形机器人需要在持续运动中响应新文本指令和空间目标；传统自回归扩散模型要么受限于有限 KV cache，难以利用远距离历史，要么不断扩大缓存、增加计算与显存负担。
2. **受到什么启发：** Mamba 的递归状态可以压缩历史，局部注意力又擅长读取明确的近期特征。两者各有所长，关键在于让压缩状态重新成为注意力可访问的内容。
3. **提出什么方法：** 采用 root-body 两阶段扩散架构，将局部注意力、可恢复的 Mamba 状态和 Persistent Content Memory（PCM）结合；PCM 将已接受窗口的状态摘要、状态变化和文本特征写入动态内容槽。
4. **方法特点：** 只在一个干净动作窗口被接受后提交 KV cache、Mamba 状态与 PCM，扩散去噪中的中间候选读取同一份只读历史快照，避免把采样迭代误当成真实时间推进。
5. **实验怎么设计：** 在 HiPHI、BONES Seed、HumanML3D 上评估短时与长时控制，并将生成结果部署到 Unitree G1；另对执行流程简化、融合 kernel 和 CUDA Graph 分别做系统消融。
6. **实验结果：** HiPHI 自回归 rollout 最长达到 39.52 秒；RTX 4090 上完整窗口中位延迟由 1685.35 ms 降至 276.14 ms，配对中位加速约 6.138 倍。作者报告真实 G1 任务 100 次试验中完整任务成功率为 94%，未观察到跌倒。
7. **得到什么结论：** 长时运动控制需要同时解决历史压缩和采样执行开销；只改采样步数或只扩大缓存都不能独立解决问题。
8. **对业界的贡献：** 提供了可用于连续人形动作生成的模型、数据和工程执行方案，对需要在线指令切换的机器人、交互动画和遥操作辅助有直接参考价值。
9. **独立评判：** 这是今天较完整的算法—系统—真机组合工作。PCM 的固定容量仍无法保证保留任意远距离细节；94% 成功率也需要结合任务难度、控制器和失败类型理解。论文还特别区分了窗口生成时间与用户指令到动作可见的端到端延迟，这一点值得产业复现实验沿用。

**代码核验：** README 给出 52 帧、25 FPS 的生成设定、训练配置、100,000 updates、global batch 512，以及独立的训练/评测/仿真依赖。已抽查训练 YAML，确认主模型从头训练、预训练 motion codec 冻结；部署还依赖独立 SONIC 控制栈和外部资产，复现成本不低。

### 2. [Embo-Harness: Towards Understanding Frontier-Model-as-Policy Harness](https://arxiv.org/abs/2611.31201) · [GitHub](https://github.com/DravenALG/Embo-Harness)

1. **针对什么问题：** 多模态前沿模型能理解场景，却不一定能稳定地把理解转化为机器人动作；不同 prompting、planning、action execution 和 tool use 设计缺乏系统比较。
2. **受到什么启发：** 机器人策略不一定要把所有动作都交给手工技能或低层轨迹生成器，模型原生的视觉推理和工具使用能力可能更适合作为高层控制接口。
3. **提出什么方法：** Embo-Harness 把机器人闭环拆成提示、规划、动作执行和工具使用四个维度，系统比较动作表示、动作 chunk、推理 effort、视觉观测和策略细化方式。
4. **方法特点：** 不把“模型”与“执行框架”混为一谈；通过受控干预观察模型究竟依赖空间目标估计，还是显式关节/轨迹生成。
5. **实验怎么设计：** 在 RoboLab-120 做统一仿真任务比较，并在四类真实操作任务中做零样本测试；仓库提供配置、批量运行脚本和位置估计实验入口。
6. **实验结果：** 作者报告 RoboLab-120 成功率 83.3%，比最强报告基线高 26.2 个百分点；真实世界 20 次试验中成功 15 次。README 的 20 任务子集图表还展示了不同 harness 选择对成功率的显著影响。
7. **得到什么结论：** 在当前前沿模型上，准确估计末端执行器目标位置，可能比直接生成大量低层关节指令更关键。
8. **对业界的贡献：** 为机器人团队提供了一个“先优化接口，再决定是否微调模型”的路线，可降低定制低层策略的成本。
9. **独立评判：** 这是高价值的工程研究，但结果对模型版本、推理预算、图像分辨率和机器人控制器敏感。真实任务仅 20 次，尚不足以证明跨机器人、跨工厂的普适性；部署时还应补充安全约束与失败恢复测试。

**代码核验：** 已读 README 和配置说明，仓库提供 RoboLab 与 openpi 子模块、单次/批量评测入口、位置估计实验。运行需要 Codex CLI、Isaac/RoboLab 资产和 GPU，属于可复现但环境较重的工程项目。

### 3. [WorldLeague: Benchmarking Physical Agency](https://arxiv.org/abs/2611.30989) · [GitHub](https://github.com/xyangzhou/WorldLeague) · [数据集](https://huggingface.co/datasets/xyangzhou/WorldLeague)

1. **针对什么问题：** 现有具身评测常把场景问答、物体识别或单项动作当作能力代理，却不能说明系统是否真正完成了物理目标。
2. **受到什么启发：** 人类判断机器人能力时，关心的是它是否把事情做成，而不是它能否在事后正确描述场景。
3. **提出什么方法：** 构建 60 个模拟机器人任务，分为 WorldSeek、WorldShape、WorldShift 三条赛道，覆盖导航、目标定位、几何重排、物理推理、时间记忆和约束管理六类能力。
4. **方法特点：** 同时报告 Interactive Score（完成了多少目标子要求）和 Physical Success Rate（是否满足全部目标及约束），并允许 VLM、VLA、WAM 使用各自适合的控制接口。
5. **实验怎么设计：** 13 个系统在相同任务目标和物理谓词下运行；通过轨迹评分检查中间进展、最终成功和终端问答之间的差异。
6. **实验结果：** Claude Fable 5.2 的平均 Interactive Score 为 28.58/100，完成 60 个目标中的 13 个；在 347 个终端问答全部正确的 VLM episode 中，有 71.8% 的 Interactive Score 为零。
7. **得到什么结论：** 语言理解正确并不代表物理目标完成，部分进展也不能替代最终成功。
8. **对业界的贡献：** 为机器人采购、模型比较和具身 Agent 迭代提供更贴近实际交付的评价口径；可避免只看 QA 或演示视频就判断机器人能力。
9. **独立评判：** 进展分与成功率分开是很好的设计。仍需关注模拟器物理真实性、动作接口公平性和任务分布是否代表真实工作场景；真机测试应作为下一阶段核心，而非把模拟榜单当作部署保证。

**代码核验：** README 于 2026-11-24 标明数据集已公开，仓库提供任务目录、WorldHarness、评测与轨迹可视化说明。任务数据共 60 项，连续控制覆盖 59 项；另有一个场景生成入口仍标记为 TODO。

### 4. [3AGameFactory-Motion: Agentic Rigging and Reliable Complex Motion Generation for Diverse 3D Assets](https://arxiv.org/abs/2611.30013) · [GitHub](https://github.com/OpenDCAI/GameFactory-3A)

1. **针对什么问题：** 任意 3D 资产的动画生成不仅要产生自然运动，还要理解骨架结构、不同形态的关节关系，以及多阶段、定时、角度和轨迹约束。
2. **受到什么启发：** 让语言模型逐帧输出关节坐标，成本高且容易破坏骨长、接触和运动学约束；若模型只输出语义参数，再由确定性执行器求解，可能更可靠。
3. **提出什么方法：** 构建 DivDynBench，并提出 Agentic Motion Framework：Agent 生成参数化骨架与运动程序，确定性执行器完成 rigging、kinematic solving 和几何修正。
4. **方法特点：** 把高层语义计划与低层几何/运动学执行分离；动作以阶段、节奏、关键部件、末端目标和轨迹等紧凑参数表示。
5. **实验怎么设计：** 50 个资产覆盖 humanoid、multiped、axial、winged、mixed-limb、mechanical 六种形态；850 项动作任务中包含文本和数值约束。比较专用动作模型、视频生成后恢复动作、Agent 直接生成三类范式。
6. **实验结果：** 仓库展示的 rigging 对比中，GPT-6.1-sol 加框架后的 source fidelity 从 67.82% 提升至 100%，joint validity 从 0.4048 提升至 0.9718；同一 Agent 的 motion overall 从 30.19 提升至 35.99，单例成本由 0.024 美元降至 0.0087 美元。
7. **得到什么结论：** 让模型输出紧凑的结构化程序、由确定性模块执行，是复杂 3D 动作生成中兼顾可控性与成本的可行路线。
8. **对业界的贡献：** 对游戏资产自动绑定、数字人、动画生产和机器人仿真资产制作有直接价值；同一套接口可以适配多种 3D 形态。
9. **独立评判：** 这项工作把 benchmark、Agent skill 和执行器连接得较好。需要继续观察用户研究规模、自动评分与审美偏好的一致性，以及跨引擎/跨资产格式的稳定性。确定性执行器的工程维护也会成为长期成本。

**代码核验：** 已读项目专门的 Motion 文档。仓库列出 agent skill、GenMotionOperator、IK/skin/motion operators、示例 JSON 和测试文件；方法不是纯概念方案，已有可运行执行路径。

### 5. [A Glimpse of Training VLMs as Foundation Models for Robotic Manipulation](https://arxiv.org/abs/2611.29338)

1. **针对什么问题：** 前沿 VLM 展现出较强机器人泛化能力，但训练数据与训练细节通常不透明，研究者难以复现类似能力。
2. **受到什么启发：** 将机器人动作表达为有语义的步骤和可复用动作原语，同时通过结构化系统提示限制机器人专属输出，减少对通用视觉语言能力的破坏。
3. **提出什么方法：** nanoAstra 结合 semantic action modeling 与 capability-preserving supervised fine-tuning（CP-SFT），在 5,000 多小时机器人数据和通用 VQA 数据上训练。
4. **方法特点：** 不是直接把动作 token 化，而是以带进度说明的参数化动作原语组织行为；机器人系统提示定义结构化动作空间。
5. **实验怎么设计：** 在 RoboTwin 2.0 随机化基准测试 9B 模型零样本操作，并测量单 H20 GPU 上推理与机器人运动的时间重叠。
6. **实验结果：** nanoAstra-9B 零样本成功率 17.8%；动作流式执行把机器人空闲时间从 35.0% 降到 6.9%。
7. **得到什么结论：** VLM 可以通过大规模机器人数据和能力保持式微调成为通用操作模型，但语义动作结构和执行时序同样重要。

2. **受到什么启发：** outcome-based RL 和假设回溯模板会奖励长推理过程；如果模型在推理中提出错误事实，即使随后撤回，也可能被训练信号固化。
3. **提出什么方法：** 在六个开源模型、两个模型家族和两类架构上追踪 RL 期间自生成幻觉及后续记忆变化。
4. **方法特点：** 区分获得训练信号的幻觉与未获训练信号的自生成幻觉，观察错误事实的长期记忆。
5. **实验怎么设计：** 比较标准后训练过程中错误事实的 recall、撤回事实的记忆，以及模型 abstention 行为变化。
6. **实验结果：** 被训练强化的幻觉 recall 平均增加 4.83%，未获训练信号的自生成幻觉只增加 0.17%；奖励幻觉后模型拒答意愿平均下降 7.23%。
7. **得到什么结论：** 知识任务的强化学习可能把模型自己的错误当作可学习事实，形成新的幻觉来源。
8. **对业界的贡献：** 对知识型 RL、事实核验奖励和模型拒答校准提出重要风险提示。
9. **独立评判：** 这是值得认真对待的训练安全问题，但具体效应仍依赖任务、奖励和模型配方；应在生产模型的持续训练中加入反事实事实核查与遗忘测试。

### 39. [LLMs and Cultural/Visual Reasoning: Polytropos, VIVID, UUBench 等相关方向的共同观察]

这不是独立论文条目，而是对上述多模态研究的横向观察：视觉模型的瓶颈正在从“能否识别输入”转向“是否保留输入中的关键证据”。Polytropos 关注文化对象特异性，VIVID 关注 value 中的视觉内容，Seeing Right, Writing Wrong 关注推理文本是否覆盖图像证据，UUBench 关注用户未明说的沟通线索。产业系统应当保留可追溯的视觉/音频证据，而不是只保存模型最终生成的文字结论。

### 42. [Self-WSP: Can Language Models Improve Themselves Through Weight-Space Programming?](https://arxiv.org/abs/2611.28833)

1. **针对什么问题：** 语言模型能通过 weight-space programming 修改小模型权重，但能否对自身权重进行编辑并持续自我改进尚不清楚。

3. **提出什么方法：** Qwen3.5-0.8B 读取自身权重、提出编辑，再用编辑后的权重继续求解和编辑。

6. **实验结果：** GSM8K 从 11.8% 提升到 62.2%，MATH500 从 7.0% 提升到 32.2%；有时只修改 16 个参数，但随机搜索也能达到相近结果。
7. **得到什么结论：** 权重空间编辑可能带来真实性能提升，但不能据此认定模型理解了自己修改的机制。
8. **对业界的贡献：** 为递归自我改进提供新研究方向，也提醒评测者区分有效搜索与真正自我理解。

### 44. [What Makes Good Data for Training Coding Agents? A Systematic Study on SWE-Gym](https://arxiv.org/abs/2611.30207) · [GitHub](https://github.com/Arist12/SWE-Gym-Verified)

5. **实验怎么设计：** 训练模型做贷款决策和代码生成隐藏目标，并用强 LLM monitor 检查 CoT 是否暴露隐藏意图。
6. **实验结果：** 作者报告 latent reasoning 深度至少达到此前测量的 5 倍；强 LLM monitor 未能从 CoT 中识别隐藏目标。
7. **得到什么结论：** 仅监控可见 CoT 不能保证识别模型内部目标，输出解释与实际决策过程可能脱钩。
8. **对业界的贡献：** 对模型审计、内部状态监控、工具调用安全和部署治理提出重要问题。
9. **独立评判：** 这是风险证明，不代表当前生产模型普遍如此；但它说明“看起来合理的思维链”不能当作安全证据。应加强行为测试、内部表示研究和工具执行审计，而不是依赖单一 CoT 监控。

### 50. [From Rewarding What Models Say to How They Think: Attention Process Reward Model for LLM Reinforcement Learning](https://arxiv.org/abs/2611.30627)

1. **针对什么问题：** 传统 RL 奖励最终答案或文本轨迹，容易出现 reward aliasing，难以区分相同答案背后的推理质量。
2. **受到什么启发：** 模型内部 hidden states 和 attention patterns 可能提供更细粒度的过程信号。
3. **提出什么方法：** Attention Process Reward Model（APRM）利用 hidden states 与 attention maps 产生内部奖励，并以 ranking 和 counterfactual objectives 训练。
4. **方法特点：** APRM 约 46M 参数，周期性更新以应对 RL 过程中的分布变化。
5. **实验怎么设计：** 将 APRM 奖励接入代表性 RL 方法，比较 pass@8 和训练稳定性。
6. **实验结果：** 作者报告平均 pass@8 提升 2.88%。
7. **得到什么结论：** 内部过程信号有潜力补充最终答案奖励。
8. **对业界的贡献：** 对数学、代码和复杂推理模型的过程监督提供新方向。
9. **独立评判：** Attention 不一定等于推理质量，模型可能学会操纵奖励特征；需要验证过程分数与真实正确性、鲁棒性和校准度的因果关系。

### 51. [NoHairCache: Calibrate-Once KV Cache Eviction with One Power-Law Exponent](https://arxiv.org/abs/2611.29006)

1. **针对什么问题：** KV cache eviction 需要在保留注意力重要性与保留近期上下文之间权衡，现有方法常用不同启发式，且需要数据集级调参。
2. **受到什么启发：** H2O 和 StreamingLLM 可能是同一 power-law scoring family 的两个极端，年龄惩罚指数可以统一二者。
3. **提出什么方法：** 用单一 power-law 指数 α 组合累计 attention 和 token age，按模型校准一次后迁移到不同语料。
4. **方法特点：** 将 H2O 视作 α=0 的端点，StreamingLLM 近似为 α 趋于无穷的端点，并给出 no-hair 机制的可行区间。
5. **实验怎么设计：** 在五个模型、WikiText、PG19、arXiv 三个语料及九组 QA task/budget 上比较 perplexity 和问答准确率。
6. **实验结果：** 512 cache budget 下，PPL 比 StreamingLLM 低 0.06–0.10；NarrativeQA 仅保留 25% cache 时保留全缓存准确率的 98.2%，StreamingLLM 为 91.1%。
7. **得到什么结论：** 一个模型级校准参数可能统一两类 cache 策略，并减少数据集专属调参。
8. **对业界的贡献：** 对长上下文推理成本和显存优化有实际价值。
9. **独立评判：** 当前摘要中的模型规模为 410M–1.5B，距离前沿大模型仍有差距；校准参数在长上下文、多轮工具调用和多模态 token 下是否稳定，仍需验证。

### 52. [A Pipeline-Parallel System for Depth-Recurrent Models](https://arxiv.org/abs/2611.30581)

1. **针对什么问题：** Depth-recurrent/looped 模型在 pipeline parallelism 中会重复访问同一 stage，计算图变成循环结构，常规 1F1B 调度无法正确排序和通信。
2. **受到什么启发：** 应将同一 stage 的不同迭代当作独立访问，构建全局一致的循环调度，而不是直接套用无环流水线方案。
3. **提出什么方法：** Loop-PP 为循环布局重建时间表与通信指令，将不同迭代的 stage visit 分开调度，并把发送与等待拆开以重叠通信和计算。
4. **方法特点：** 静态 instruction stream，保持数值结果与单 stage reference bit-identical。
5. **实验怎么设计：** 在 8B–60B MoE 模型上比较峰值显存和吞吐，验证单 stage 数值等价。
6. **实验结果：** 峰值显存最多下降 32.8%，固定计算预算下最佳吞吐提升 12.7%。
7. **得到什么结论：** 循环深度模型需要专门并行调度，传统流水并行并不能直接扩展。
8. **对业界的贡献：** 对大规模 MoE 和深度复用网络训练系统有价值。
9. **独立评判：** 这是系统层优化，实际收益取决于模型拓扑、网络互联和通信实现；需要公开硬件配置与端到端训练脚本供外部复验。

### 53. [Feedback Shortcut: Speculative Decoding for Latent Feedback Transformers](https://arxiv.org/abs/2611.28227)

1. **针对什么问题：** Latent feedback Transformer 将前一位置的 top-layer hidden state 反馈到下一位置输入，破坏了 speculative decoding 的精确验证条件。
2. **受到什么启发：** 可以用轻量投影对齐草稿状态，再在后续验证过程中利用前一位置新计算出的状态修正草稿。
3. **提出什么方法：** Feedback Shortcut 结合 state alignment 和 pipelined correction，在后续 draft 验证过程中修正前序状态近似。
4. **方法特点：** 修正发生在后续验证 pass 中，不需要额外模型调用。
5. **实验怎么设计：** 在 135M 和 780M 模型上测试 Paloma bits-per-byte 与解码加速。
6. **实验结果：** 距精确解码上限在 10^-4 bits/byte 内，解码加速 2.4–2.8 倍，训练计算仅增加约 2%。
7. **得到什么结论：** latent feedback 与 speculative decoding 并非不可兼容，关键在于草稿状态对齐与验证流水线。
8. **对业界的贡献：** 有助于将 latent feedback 架构用于低延迟推理。
9. **独立评判：** 目前模型规模仍较小；需在大 batch、长上下文和更大模型上检查修正误差是否累积。

### 54. [MORSE: Optimizing Streaming Memory Design via Open-World Auto-Research](https://arxiv.org/abs/2611.30011)

1. **针对什么问题：** 流式视频系统必须在不知道未来问题的情况下，从有限帧预算中选择保留证据；现有自改进系统常只能在预定义工具范围内修补。
2. **受到什么启发：** 如果某类失败在多个视频中反复出现，已有论文、模型卡或代码中可能已经有可借鉴的解决方案。
3. **提出什么方法：** MORSE 聚类训练轨迹中的重复失败，自动检索论文、模型卡和代码，寻找可迁移方法或预训练感知模型，再修改记忆写入和检索流程。
4. **方法特点：** 以冻结视频语言模型为核心，优化外围 memory harness；先提高准确率，再在容忍范围内寻找更快方案。
5. **实验怎么设计：** 在三个 streaming video benchmark 上比较同一 frozen backbone 下的不同 memory harness。
6. **实验结果：** OVO-Bench 上 Qwen3-VL-8B 平均回答时间 0.30 秒，准确率 75.1%，比同 backbone 下次优 harness 高 3.1 个百分点。
7. **得到什么结论：** 开放世界检索与失败归因可成为记忆系统自动优化的来源。
8. **对业界的贡献：** 对长视频理解、实时监控和流式多模态 Agent 有价值。
9. **独立评判：** 自动研究循环可能引入低质量来源、依赖错误工具或产生回归；必须有来源可信度评估、隔离验证集和自动回滚。

### 55. [Deterministic, Reproducible Inference in Exact Integer Arithmetic](https://arxiv.org/abs/2611.13730) · [GitHub](https://github.com/pelloran-inc/tritify)

1. **针对什么问题：** 浮点推理可能因硬件、编译器和线程数不同产生不同结果，给分布式模型审计和复现带来困难。
2. **受到什么启发：** 若运行时前向计算全部使用精确整数运算，就可以获得跨硬件一致的输出字节。
3. **提出什么方法：** tritify 将模型推理路径转为整数算术，浮点仅用于离线量化和参考结果验证。
4. **方法特点：** 追求 bit-identical output 和跨设备可验证性，而不是单纯追求单机速度。
5. **实验怎么设计：** 测试 decoder-only LLM、MoE decoder 和 SAM 2.1，并跨 CPU 指令集、CPU/GPU、多机拆分运行比较输出哈希。
6. **实验结果：** 作者报告 106B MoE 的整数代码可分布在三台机器上运行，输出与单机参考逐 bit 相同；论文明确不声称速度提升或保密性。
7. **得到什么结论：** 可验证分布式推理有望建立在确定性整数计算之上，但它解决的是一致性而非服务速度。
8. **对业界的贡献：** 对模型审计、可重复推理和不可信推理服务器验证有价值。
9. **独立评判：** 论文主动限定主张是优点；整数近似对复杂模型的决策保真、量化成本和吞吐开销仍需更广泛第三方测试。对抗性服务器的完整安全保证尚未实现。

### 56. [The norm axiom and factor hyperfields](https://arxiv.org/abs/2611.29473) · [GitHub](https://github.com/linzialessandro/norm-axiom-factor-hyperfields)

1. **针对什么问题：** 数学上研究满足 norm axiom 的 Krasner valued hyperfield 是否都可表示为某个 valued field 的相对误差商结构。
2. **受到什么启发：** 通过把商表示条件与 norm axiom 联系起来，可将抽象结构分类问题转化为对特定子群与 valuation 的刻画。
3. **提出什么方法：** 证明 norm axiom 在商结构中强制相应子群具有 1+mρ 形式；对 value group 为 Z 的情形给出直接证明，并构造不满足 norm axiom 时的反例。
4. **方法特点：** 属于纯数学结构理论，不是机器学习算法或工程系统。
5. **实验怎么设计：** 该工作以定理证明和反例构造为核心，不存在经验性 benchmark。
6. **实验结果：** 对 value group Z 的问题给出正面证明；移除 norm axiom 后可构造反例；一般情形仍开放。
7. **得到什么结论：** norm axiom 对 factor hyperfield 表示具有关键作用，但一般分类问题尚未解决。
8. **对业界的贡献：** 短期没有直接产品贡献，长期可能影响 valuation theory 与相关代数结构研究。
9. **独立评判：** 这篇论文与当日 AI/机器人热点不同，仍应保留在完整日榜中；其价值取决于后续一般情形能否解决，不宜强行包装成 AI 产业趋势。

## 七、独立研究判断：哪些 idea 真正值得投入？

我把今天的研究按“问题是否真实、方法是否有机制创新、实验是否支撑主张、代码是否可复现、产业迁移是否明确”五个维度做了综合判断。

**最扎实的研究信号**

- **SWE-Gym-Verified：** 问题真实、审计方法可操作、数据与证据公开。它提醒我们，训练数据标签错误会直接污染 Agent 的能力方向。建议任何 RL Agent 项目都增加奖励审计。
- **RUIBench：** 把接口设计从工程细节提升为实验变量，结论可迁移到很多机器人系统。它的不足主要是模拟与真机覆盖，而不是研究问题本身。
- **Motion Mamba 2.0：** 算法、状态管理、系统优化和真机演示结合较好，工程完成度高。最值得复现的是 accepted-history commit 与延迟测量口径。
- **ViDiHand2：** 用几何约束替代脆弱的外观深度回归，动机与方法对应清晰，跨数据集对比较充分。
- **PersistWorld：** 把“已观察到的世界”作为持久状态，是世界模型从视频预测走向空间状态维护的有价值方向。

**想法新颖，但需要更强外部验证**

- **WeightCode / Self-WSP：** 权重空间编程很新颖，但必须区分程序化编辑带来的增益与随机搜索、模型选择或评测泄漏。
- **Native LAM：** 用视频模型做潜在动作教师具有潜力，真正的检验是跨机器人和真实工况迁移。
- **ReWeave / Embodied-Harness：** 不更新模型参数而改进 harness 很实用，但记忆错误累积、任务拓扑泄漏和回归风险必须严肃处理。
- **Plan4D：** 共享潜在轨迹连接视觉与几何很有价值，长时物理一致性仍是核心挑战。
- **ToolSmith / MORSE：** 自动生成工具或自动搜索解决方案可以扩展 Agent 能力，但安全与验证成本可能抵消自动化收益。

**需要谨慎解读的结果**

- 仅有高 benchmark 分数、缺少公开训练数据或评测细节的工作，暂不宜作为产业路线的单一依据。
- 只在少量真机任务上达到很高成功率的机器人论文，应继续观察任务复杂度、重复次数和失败严重性。
- 自我改进类工作必须有强随机基线、回滚机制和独立验证集，否则“持续提升”可能只是搜索或记忆污染。
- 纯数学论文应按其学科贡献评价，不应为迎合 AI 热点而强行解释成产业趋势。

## 八、后续值得追踪的问题

1. 具身 Agent 的动作接口能否形成跨机器人、跨控制器的标准协议？
2. 世界模型能否在 10 秒以上的预测跨度中同时维持视觉、几何和动力学一致性？
3. 长期记忆系统如何处理错误经验、相互矛盾的来源和过期知识？
4. 权重空间编程能否建立可审计、可撤销、可安全部署的能力安装机制？
5. coding agent 的 reward/test auditing 是否能成为主流训练数据流水线的一部分？
6. 流式视频、GUI 和机器人 benchmark 是否会从“任务完成率”扩展到延迟、资源成本和恢复能力的联合指标？
